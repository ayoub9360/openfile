# Document assistant

[Back to README](../README.md) · [User guide](usage.md)

The interface is under **Assistant** (`/search`). Without AI, it returns passages
through text search. With a configured key and AI mode saved, it can search, read,
and compare documents, then cite its sources. Answers may contain errors: check
the source documents.

## How it works and its limits

The assistant uses `ToolLoopAgent` (AI SDK 7) in the Express backend. The model
receives recent history and chooses to answer, ask for clarification, or use six
read-only tools:

- `listFacets`: available tags, folders, issuers, and types, with counts;
- `findDocuments`: metadata filters, sorting, exact totals, and pagination;
- `searchPassages`: French/English full-text and semantic search with rank fusion;
  only these calls compute a query embedding;
- `readDocument`: reads extracted text by offset, indicating whether more remains;
- `countDocuments`: exact counts with filters, including a folder alone or with
  its subfolders (`includeSubfolders`);
- `displayDocuments`: interactive file cards with a preview, name, and storage.

`searchPassages` accepts `text`, `semantic`, and `hybrid` modes. Text mode does not
compute embeddings. Filters (name, tags, dates, folder, type, and issuer) can be
combined. `displayDocuments` revalidates requested IDs and cannot display files
from another account or outside the selected scope.

References appear as named badges in Markdown text. Clicking opens the document;
hovering shows the excerpt. File cards use the existing authenticated preview
endpoint. The activity panel displays operations, their user-facing descriptions,
results, and statuses; it does not expose the model's internal reasoning. These
elements are persisted with the conversation. Markdown rendering uses
`react-markdown` and `remark-gfm`, without raw HTML or loading arbitrary images or
links generated by the model.

Conversations are stored in `conversations` and `conversation_messages`
(migration 3), separately from the workspace. The server reloads its own history;
the client sends only a new message with a unique ID. Concurrent turns and
duplicates are rejected. Completed, failed, or interrupted responses retain their
status, operations, and consulted references. A turn lost after a server shutdown
can be recovered after three minutes.

The authenticated routes `/api/conversations`, `/api/conversations/:id`, and
`/api/conversations/:id/messages` support creation, resuming, and sending. The last
route streams domain events as NDJSON; a dedicated frontend transport consumes
it without depending on internal SDK types. The interface provides the 50 most
recent conversations, streaming, operations, clickable sources, and the ability
to stop a response. The URL retains the selected conversation so it can be restored
after a reload. Changing the scope starts a new conversation.

All tools check the user, selected storage, and `filed` status. Older answers whose
sources have changed or become inaccessible are removed from the model's context.
Displayed references come from the tools and are associated with a fingerprint of
the extracted text and revision; page numbers are not available. Answers follow
the user's language.

After an empty search, a bounded policy requires a content search, facet
discovery, and then another metadata search while no result has been found. Exact
counts do not trigger this recovery. The model remains responsible for choosing
queries and filters.

Per-turn limits: ten model steps (the last is reserved for the answer), twelve
operations, 60,000 characters of results sent to the model, and two minutes.
History sent to the model is limited to the last 30 complete messages and 40,000
characters, without reinserting large previous results. Long documents remain
limited to the text extracted by the import pipeline (160,000 characters).
Without AI, the same screen provides text search. If embeddings fail, the agent
can continue with text results. The legacy `/api/search/answer` endpoint remains
available for compatibility.

Server tests include a simulated model to check clarification without tools and
the search → read → answer loop, along with PostgreSQL tests for filters, sources,
access rights, duplicates, and interruptions. No local test calls a real AI provider.
