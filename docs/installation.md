# Installation and configuration

[Back to README](../README.md)

## With Docker Compose

Prerequisites: Docker Engine, the Compose plugin, and Node.js for `scripts/setup.mjs`.
The image builds the project with Node 22.23.3 and pnpm 12.8.1; pnpm is not required
on the host for this method.

```bash
node scripts/setup.mjs
docker compose up --build -d
docker compose ps
curl --fail http://localhost:3000/api/health
```

Open http://localhost:3000 and create an account (minimum password length:
12 characters) using the invitation code in `SIGNUP_TOKEN` in your private `.env`. Clear that variable to close registration. No administrator or demo account is created in advance.

| Service    | Role                                        | Default exposure          |
| ---------- | ------------------------------------------- | ------------------------- |
| `frontend` | Next.js and `/api` proxy                    | `127.0.0.1:3000` |
| `backend`  | Express and sessions           | Docker network, port 3001 |
| `migrate`  | One-shot migrations and restricted SQL role | No published port |
| `worker`   | Extraction, analysis, indexing, and cleanup | No published port         |
| `database` | PostgreSQL 17 and pgvector                  | `127.0.0.1:55432`         |

`docker compose down` preserves volumes. Do not add `-v` if you need to keep the
data. For remote access, read [Operations](operations.md).

## Environment variables

The script generates `.env` with random secrets and `0600` permissions, without
overwriting an existing file. [.env.example](../.env.example) is an example without
secrets. Do not replace the generated file with this empty example.

| Variable                                   | Purpose                                                        |
| ------------------------------------------ | -------------------------------------------------------------- |
| `POSTGRES_PASSWORD`                        | PostgreSQL password generated by the script                    |
| `POSTGRES_USER`, `POSTGRES_DB`             | Docker role and database, default `openfile`                   |
| `APP_DATABASE_PASSWORD` | Restricted runtime role password (64 hex characters) |
| `MIGRATION_DATABASE_URL` | Administrator connection used only for migrations and isolated tests |
| `SIGNUP_TOKEN` | Invitation code; empty disables registration |
| `DATABASE_URL`                             | Connection outside Docker; Compose builds its own internal URL |
| `BETTER_AUTH_SECRET`                       | Session secret, at least 32 characters                         |
| `ENCRYPTION_KEY`                           | 64 hexadecimal characters, encrypts integration secrets        |
| `APP_URL`                                  | Canonical application origin, default `http://localhost:3000`  |
| `TRUSTED_ORIGINS`                          | Additional exact origins, separated by commas                  |
| `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET` | Optional Google OAuth application credentials                  |
| `STORAGE_ROOT`                             | Outside Docker: absolute server path; default `.data/files`    |
| `HOST`, `PORT`                             | Outside Docker: API listen address, default `127.0.0.1:3001`   |
| `API_INTERNAL_URL`                         | Next.js proxy destination, default `http://127.0.0.1:3001`     |
| `NODE_ENV`                                 | `production` in containers                                     |
| `COMPOSE_PROJECT_NAME`                     | Optional: preserve the name of an existing installation        |

The public URL must match the origin used in the browser. An origin includes the
protocol, host, and optional port, without a path or trailing slash. `APP_URL` is
also included in the allowed origins. Never use a wildcard to work around an
origin issue.

In Compose, `STORAGE_ROOT` is set to `/data/files`. For a bind mount, point the
mounts for **both backend and worker** to the same directory, writable by UID 1000.
The local folder is on the server, not the visitor's computer. AI keys are
configured in the interface, separately for each account.

After changing `.env`: run `docker compose up -d`. If the internal proxy address
changes, also check its value at frontend build time: rewrites are defined in
`apps/web/next.config.ts`.

## Google Drive

1. In Google Cloud, enable Google Drive API and configure OAuth consent.
2. Create an OAuth client of type Web application. If the project is in testing,
   add the account you will use to the test users.
3. Add exactly `APP_URL/api/connectors/drive/callback` to the redirect URIs,
   replacing `APP_URL` with its value (for example,
   `http://localhost:3000/api/connectors/drive/callback`).
4. Set the Google variables, then run `docker compose up -d`.
5. In **Connectors**, connect Google Drive and authorize your account.

Use an HTTPS origin for remote access. The connector requests the `drive.file`
scope. It does not browse your existing Drive or synchronize a watched folder.
Originals sent to Drive pass through memory and then remain in Drive; the database
stores their references and extracted text.

The root folder name can be changed in **Settings** and applies to subsequent
imports without moving existing files. After disconnecting, reconnect the same
Google account to access the originals again.

## AI and indexing

In **Settings**, select **Automatically with AI**, enter an OpenAI key, choose a
model available to that account, and click **Save and enable AI**.
OpenAI is the implemented provider; model availability depends on the account.
Embeddings use 1536 dimensions. The two models accepted in settings are
`text-embedding-3-small` and `text-embedding-3-large`. After changing the model or
enabling AI, rerun analysis on existing documents: embeddings from different
models are not compared with one another.

## Local development

Use the Node version in [.nvmrc](../.nvmrc) and the pnpm version in
[package.json](../package.json), currently 12.8.1. The declared engine range is
Node `^22.18.0 || >=24.11.0`.

```bash
# With nvm, if installed:
nvm install
nvm use
npm install --global pnpm@12.8.1
pnpm install --frozen-lockfile
node scripts/setup.mjs
docker compose up -d database
```

If the Docker application services are already running, stop them before starting
their local equivalents to avoid port and worker conflicts:

```bash
docker compose stop frontend backend worker
```

Then start three terminals from the project root:

```bash
pnpm --filter @open-file/server dev
```

```bash
pnpm --filter @open-file/server worker
```

```bash
pnpm --filter @open-file/web dev --hostname 0.0.0.0
```

The backend loads `.env`, initializes migrations, and uses PostgreSQL at
`127.0.0.1:55432`. For development mode, keep `APP_URL` on localhost or explicitly
configure your origins and, if needed, `allowedDevOrigins` in Next.js.
[Validation commands](../CONTRIBUTING.md) are documented separately.

## Existing installations

Preserve `COMPOSE_PROJECT_NAME`, `POSTGRES_USER`, `POSTGRES_DB`, `DATABASE_URL`, and
the secrets associated with already initialized volumes. The default Compose
project name is `open-file`. Changing the project name may select new volumes;
changing the role or password in `.env` does not modify an existing database.
Back up before any migration.

For an existing installation, follow [Security migration](security-hardening.md) before rebuilding. HTTP origins are accepted only on loopback; remote access requires HTTPS.
